# 圃場コードの読み取り

日誌の圃場欄は現場の手書き感覚で入力されており、そのままでは台帳の圃場名に対応しない。

## 表記のゆれ（実例）

| 種類 | 実例 |
|---|---|
| 単独 | `C` `1B` `日野` `東井出C` |
| ドット区切り | `C.N.O.P.R` |
| 空白区切り | `A DM S C N O` `N O` `K F` |
| 全角 | `ＰＴＵＲ` `Ｖ` `Ｘ` `Ｙ` |
| 長い連結 | `N O P C A I DM T U R` `S T U R` |
| 圃場＋施設 | `北小　集出荷場` `集出荷場 J` `GAGB北小` |
| 「その他」列 | `長沢;S C K　農場周り` `長沢;ＡI S Z C H N O P Y 東井出; B C` `Z K 1F` |
| タイポ | `集出荷状`（集出荷場） |

## 解釈ルール

1. **NFKC正規化** で全角英数を半角へ。`、` `，` `.` `;` `:` `・` `/` は空白に統一
2. **地区名を除去**（`東井出C` → `C`）。長い地区名から順に消す（`窪長沢` を `長沢` より先に）
3. **圃場でない呼称を除去**（集出荷場・施設名・「周辺」「ハウス」など）。長いものから順に
4. **左から貪欲に切り出す**。2文字コード（`1A` `DM`）を1文字より優先
5. 残った文字は**未解釈として報告**する。黙って捨てない

## 1行に複数圃場

`C.N.O.P.R` の1行は「C・N・O・P・R の5圃場で同じ作業をした」意味。
**該当する全圃場のシートに同じ作業として展開する。**

肥料量などは合計値なので圃場ごとの按分はできない。だから使用量は載せず種類だけ記録する運用になっている。

## 「その他」列

圃場列に入りきらない記録が「その他」列に `長沢;S C K　農場周り` の形で書かれる。
地区名の出現位置で区切り、地区ごとにトークナイズする。
`窪長沢` は `長沢` を部分文字列として含むため、**長い方を優先して重複検出を潰す**こと。

## 台帳にないコード

| コード | 扱い |
|---|---|
| 親圃場の細分（`GA` `GB` など） | `aliases` で親圃場へ寄せる |
| 常に一体で記録される2圃場（`DM` など） | `mergedFields` で1シートに統合。面積は台帳の合算 |
| 施設・屋号・「周辺」 | `nonFieldLabels` で除外 |

**統合か展開かは必ずユーザーに確認する。** `DM` を「D と M の両方に展開」と解釈して
中身が完全に同一の重複シートを2枚作った事故がある。判断材料として
「そのコードが単独で出現するか」を数えて示すとよい（`D` `M` の単独記載は0件だった）。

## 検算

`extract.py` の「未解釈が残った圃場セル」が**0件になるまで** `nonFieldLabels` / `aliases` を調整する。
0件になっても、圃場別の件数が不自然に少なければ取りこぼしを疑うこと。
