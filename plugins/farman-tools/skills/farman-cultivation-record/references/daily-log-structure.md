# 作業日誌の構造と読み取り

## 全体像

- 月ごとに1タブ（`<和暦プレフィックス><月>` 例: `R7.1` … `R7.12`）
- 別に「委託作業系」タブ（外部委託・受託作業）と参照用データのタブがある
- 見出しは1〜2行、データはその次の行から。**月によって見出しが2行の月と3行の月がある**

## 列の並び（代表例）

| 見出し | 内容 |
|---|---|
| 日付 / 天気 / 作業者… | 先頭ブロック |
| **圃場** | 地区ごとに横に並ぶ（長沢／東井出／長坂／穴山／その他 等）。年によって顔ぶれが違う |
| 内容（栽培関係） / 内容（その他） | 作業内容。古い年は「作業内容」1列だけ |
| 作物 / 品種 / 仕入れ先 / 使用機械 | |
| **重量情報** | kg及びℓ / 個数 / **合計kg数** |
| **定植・播種情報** | ○穴 / 粒 / 枚数 / **合計粒** ← 苗・種の使用数はここ |
| 備考 | |

`重量情報` `定植・播種情報` は結合セルの見出し。実データは
**見出し列 +2（合計kg数）／+3（合計粒）** にある。

## 取得経路（重要）

| 経路 | 可否 | 理由 |
|---|---|---|
| **xlsxダウンロード** | ⭕ 唯一確実 | フィルタ・行数の影響を受けない |
| gviz / CSVエクスポート | ❌ | タブに絞り込みが残っていると**表示中の行しか返らない** |
| Drive APIコネクタ | ❌ | 各タブ**約45行で打ち切られる** |

実例: ある年の日誌をgvizで取ると 4月2行・5月3行・7月8行しか返らなかったが、
実際は各44〜63行あった。7月は特定圃場の行だけが返り、絞り込みが残っていると気付けた。

## 列ずれ

同じ年でも、**ある月から作物以降が1列右にずれる**ことがある（列の挿入跡が残る）。

| | 作物 | 品種 | 合計粒 |
|---|---|---|---|
| 4〜10月 | V列 | W列 | AF列 |
| **11〜12月** | **W列** | **X列** | **AG列** |

固定列番号で読むと、空のV列を「作物」として読み、定植数量を丸ごと落とす。
実例: `定植 タマネギ/ターボ 32,320本` が欠落した。

→ **必ず見出し行から列位置を実測する**（`resolve_cols()`）。

## 数量セルの型

合計粒・合計kg数の欄に **文字列で** 数字が入っている行がある（`'4000'` `'700'`）。
数値型だけを拾う実装だと消える。→ `to_num()` で文字列も数値化する。

また `最終日に記載` のように、数量ではなく指示が書かれている行もある。
この場合は総数が別行に無いことが多く、**数量不明として塗りつぶす**のが正しい。

## タブの並び順

日誌は**新しい月が左**に並んでいることがある。`wb.sheetnames` の順で処理すると
肥料・機械・作物の一覧が逆順になる。**必ず月番号でソートしてから処理する。**
