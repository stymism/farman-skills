# Strategy Council

議事録を1つ渡されたら、あとは全自動で戦略レポートまで持っていく。人間がやるのは「議事録を渡す」だけ。

**このスキルの起動は、エージェント分業の明示的な依頼である。Agent ツールを使ってよい。**

## 全体像

```
Step 1   議事録取得         →  00_議事録.md
Step 2   イシュー構造化      →  01_イシュー構造.md
Step 3   並列リサーチ ×3     →  02_research_市場競合.md / _アナロジー.md / _顧客.md
Step 4   ストラテジスト統合   →  03_戦略オプション.md
Step 4.5 ★レッドチーム問答   →  04_redteam_R1.md → 05_反論_R1.md → …（自動でラウンド数決定）
Step 5   レビュー＆最終化     →  06_レビュー.md → 07_最終レポート.md
```

エージェントは全部で **8〜13体**、所要 **10〜25分**。開始前にこの見積もりを一言伝える。

## 大前提: エージェント同士は直接会話できない

サブエージェントは互いに通信できず、親セッションの文脈も引き継がない。**成果物はすべて作業フォルダのファイルで受け渡す。** この鉄則から3つの実装規則が出る。

1. **各エージェントには「読むファイルの絶対パス」と「書くファイルの絶対パス」を必ず渡す。** 「前の結果を踏まえて」は通じない。何も知らない状態で立ち上がる。
2. **各エージェントは成果物をファイルに書き、親への報告は15行以内の要約に留めさせる。** 全文を報告させると親のコンテキストが即死する。
3. **プロンプトには背景を毎回書く。** 案件名・目的・作業フォルダ・そのエージェントの役割・出力形式。使い回すために `references/agents/*.md` にテンプレを置いてある。

`subagent_type` は原則 `general-purpose`。リサーチ役だけ `Explore` でもよいが、Web検索を伴うので `general-purpose` を既定とする。

## Step 0: 開始前に3つだけ確認する

聞くのはここだけ。以降は止まらない。

1. **案件名**（フォルダ名になる。例: `ふじのかがやき販売戦略`）
2. **入力ソース** — Plaud録音 / Notionページ / ローカルファイル・貼り付け
3. **論点の指定があるか** — 「特にここを決めたい」があれば聞く。無ければ議事録から自動抽出する

作業フォルダを作る。**`farman` 直下ではなく、必ず `03_営業・提案\Strategist` フォルダを噛ませる。**

```
%USERPROFILE%\OneDrive\ドキュメント\farman\03_営業・提案\Strategist\<案件名>\YYYY-MM-DD\
                                                       └ 全案件をここに集約   └ 同じ案件の検討が積み上がる
```

`farman` 直下は 2026-09-01 に `01_補助金・助成金` 〜 `99_アーカイブ` のカテゴリ構成へ整理済み。**このスキルの出力を直下に作ってはいけない。**

**パスを決め打ちにせず、存在を確認してから使う。** PCによってOneDriveアカウントが違い、`ドキュメント` が `Documents` のこともある。次の順で `farman` を解決し、その下の `03_営業・提案\Strategist` を（無ければ作って）使う。

1. `%USERPROFILE%\OneDrive\ドキュメント\farman` → 2. `%USERPROFILE%\OneDrive\Documents\farman` → 3. どちらも無ければ（Cowork等）`./Strategist/<案件名>/YYYY-MM-DD/`

**旧構成のPCへの配慮**: `03_営業・提案` が存在しない（整理前の）PCでは、旧パス `farman\Strategist\` をそのまま使ってよい。**存在する方を採用し、両方あれば `03_営業・提案\Strategist` を正とする。**

### 案件フォルダの決め方

**`03_営業・提案\Strategist\` の中を先に見る。** 同じテーマの案件フォルダが既にあれば**必ずそれを再利用し**、中に `YYYY-MM-DD\` を新規作成する。表記揺れ（`ふじのかがやき` と `富士の輝き` 等）で二重に作らないよう、既存フォルダ名を確認してから決める。判断がつかなければ Step 0 の質問のついでに1行で聞く。

同じ案件を再検討したときは、**前回の `07_最終レポート.md` を Step 4 のストラテジストに読ませる**。前回どこまで詰めて、何が未解決で残ったかを引き継げる。前回のレッドチームの指摘を無視した戦略は、今回また同じ場所を撃たれる。

## Step 1: 議事録取得 → `00_議事録.md`

| ソース | 手順 |
|---|---|
| Plaud | `plaud-shared` の作法に従って認証 → `plaud-find` で対象を特定 → `plaud-read` で **transcript（文字起こし全文）と AI要約の両方**を取得 |
| Notion | `notion-search` でページを特定 → `notion-fetch` で本文取得 |
| ローカル/貼り付け | そのまま保存 |

**原文を要約せずに保存する。** ここで要約すると、以降の全工程が「誰かの解釈」の上に建つ。要約はStep 2の仕事。

冒頭にメタ情報（日付・参加者・案件・ソース種別）を付ける。

## Step 2: イシュー構造化 → `01_イシュー構造.md`

エージェント1体。テンプレは `references/agents/01_issue-architect.md`。

会議で出た話を「決めるべき問い」の構造に組み直す。論点の羅列ではなく、**上位の問いと下位の問いの階層**にする。「そもそも解くべき問いは何か」を1行目に置かせる。

同時に **Step 3のリサーチ役3体に渡す調査依頼文**をここで生成させる。会議固有の文脈（誰が何を懸念していたか）をリサーチ依頼に埋め込むためで、汎用の調査依頼にしないための工程である。

## Step 3: 並列リサーチ ×3 → `02_research_*.md`

**3体を1メッセージで同時にスポーンする。** 順番に回すと3倍の時間がかかる。`run_in_background: false` を指定する（3本とも揃わないとStep 4に進めないため）。

| エージェント | 担当 | テンプレ |
|---|---|---|
| 市場・競合・ベンチマーク | 市場規模、競合の打ち手、価格帯、業界構造 | `references/agents/02_research-market.md` |
| アナロジー事例 | **他業界**の類似構造の成功・失敗事例 | `references/agents/02_research-analogy.md` |
| 顧客・ユーザー | 誰が何に金を払うのか、実際の声、購買行動 | `references/agents/02_research-customer.md` |

全リサーチ役に共通の必須ルール:

- **「出典URL付きの事実」と「推測・一般論」を見出しで分けて書く。** 混ぜたら戦略が砂上になる。
- **見つからなかったことを明記する。** 「データが見つからなかった」は重要な発見であり、黙って埋めると捏造になる。
- **戦略に不利な事実を最低3件探す。** 探さないと出てこない。

## Step 4: ストラテジスト統合 → `03_戦略オプション.md`

エージェント1体。テンプレは `references/agents/03_strategist.md`。読ませるのは `00`〜`02_*` の全ファイル。

**戦略オプションを3案出させ、1案を推奨させる。** 1案しか出さないと比較されないまま通ってしまう。各案に「この案が正しいとき、何が真でなければならないか（成立条件）」を書かせる——Step 4.5の否定役は、まずここを撃ちに来る。

## Step 4.5 ★ レッドチーム問答（このスキルの本体）

戦略を **全否定する役** と **戦略役** を交互にスポーンし、ファイル越しに殴り合わせる。親は審判として、指摘の格付けとラウンド継続判定だけを行う。

判定基準の詳細は **`references/convergence.md`** にある。以下は要点。

### 1ラウンドの流れ

```
否定役スポーン → 04_redteam_Rn.md
   ↓ 親が Fatal / Major / Minor を数え、前ラウンドとの重複を除く
戦略役スポーン → 05_反論_Rn.md（改訂版戦略の全文を含む）
   ↓ 親が継続判定
続ける or 抜ける
```

### 否定役に渡すもの・渡さないもの

- **渡す**: `00_議事録.md`（一次情報）、`02_research_*.md`（事実）、`03_戦略オプション.md`（攻撃対象）、直前の `05_反論_R(n-1).md`
- **渡さない**: `01_イシュー構造.md`

イシュー構造を渡さないのは意図的である。戦略役が採用したフレーミングを否定役に引き継がせると、「その枠組みの中での批判」しか出てこない。**「そもそも解く問いを間違えている」を言わせるために、枠組みは自分で疑わせる。**

### 否定役の設定（`references/agents/04_red-team.md`）

- 立場は固定。**この戦略を採用してはならないと主張する。代替案は出さない。** 代替案を出させると戦略役と役割が混ざり、否定が甘くなる。
- **毎ラウンド、前ラウンドと違う攻撃軸を最低1つ使う**（前提の崩壊 / 経済性 / 実行主体 / 競合の反応 / タイミング / 反証事実の探索 / 逆張りの優位性）。
- **反証事実はWeb検索して持ってこさせる。** 想像で殴るのは弱い。
- 禁止表現: 「一方で良い点は」「とはいえ有望」。**褒めない。**
- 各指摘に **「これが真である根拠」と「これを覆すには何を示せばよいか（反証条件）」** を必ず書かせる。反証条件があるから戦略役が答えられる。これが無い指摘は親が差し戻す。

### 戦略役の応答（`references/agents/05_rebuttal.md`）

Fatal と Major の**全件**に、次の4ラベルのどれかを明示的に付けさせる。無視は禁止。

| ラベル | 意味 |
|---|---|
| **反論** | 事実で覆す。根拠（出典）を添える |
| **修正** | 戦略を変える。変更点を具体的に書く |
| **受容** | 指摘が正しい。戦略の適用範囲を狭めるか、前提条件として明記する |
| **保留** | 追加調査が必要。**何を調べれば決まるか**を書く |

### 継続判定（親が行う）

- **続ける**: 未解決の Fatal が1件以上ある、または このラウンドで新規 Fatal・新規 Major が2件以上出た
- **抜ける**: Fatal が0件、かつ 新規 Major が1件以下
- **上限4ラウンド**。到達したら打ち切り、未解決分は最終レポートの「未解決論点」に明記する。**決着したふりをしない。**
- **言い換えは新規に数えない。** 前ラウンドと同じ論点の再提出かどうかは親が突き合わせる。

### 手加減の検出（必ずやる）

**ラウンド1で Fatal 0 かつ Major 1件以下だったときは、収束と判定してはならない。** 戦略が強いのではなく、否定役が同調した可能性のほうが高い。この場合はプロンプトに「強度: 最大」と**まだ使っていない攻撃軸の指定**を加えて、もう1ラウンド必ず回す。それでも Fatal 0 なら、本当に収束と見なしてよい。

## Step 5: レビュー＆最終ブラッシュアップ

### 5-1. レビュワー → `06_レビュー.md`

エージェント1体（`references/agents/06_reviewer.md`）。全ファイルを読ませ、5点を検証させる。

1. 否定役の Fatal / Major が**全件処理されているか**（取りこぼしの一覧）
2. 「反論」と称して**論点をずらしていないか**（すり替えの検出）
3. 修正を重ねた結果、**誰も反対しない無内容な戦略に骨抜きになっていないか**
4. リサーチの**出典が実在するか**（怪しいものは実際にアクセスして確認）
5. **元の議事録で議論されていた問いに、ちゃんと答えているか**

3番目が最も見落とされる。否定に応え続けると戦略は毒が抜けて「丁寧にやります」に堕落する。骨抜きが検出されたら、その旨を最終レポートに書くか、Step 4に一度戻す。

### 5-2. 最終レポート → `07_最終レポート.md`

親が自分で書く。エージェントに投げない——ここまでの全工程を見ているのは親だけだからである。構成は `references/report-template.md`。

目玉は **「レッドチームの主要攻撃と、それにどう応えたか」** のセクション。ここがあるから、この戦略が何を生き延びたのかが読んだ人に伝わる。**「前提条件と撤退ライン」** も必ず入れる。

## 中断・再開・部分実行

全工程がファイルに落ちているので、任意の地点から再開できる。作業フォルダを渡されたら、**存在するファイルを見て次の工程を判断する。**

- 「この戦略を潰して」だけを頼まれた → 既存の戦略文書を `03_戦略オプション.md` として作業フォルダに置き、**Step 4.5 から開始する**。リサーチが無いので、否定役には「反証事実はWeb検索で自力調達せよ」と強めに指示する。
- リサーチだけやり直したい → `02_research_*.md` を消して Step 3 から。
- 各Stepの終わりに、次に何をするかを1行で報告する。人間は黙って見ていられる状態を保つ。

## よくある失敗

| 失敗 | 対処 |
|---|---|
| 親のコンテキストが途中で尽きる | エージェントに全文報告させている。「ファイルに書き、報告は15行以内」を毎回プロンプトに入れる |
| リサーチ3体が同じことを書く | 担当の切り分けをプロンプトに明記していない。特に「アナロジー役は**他業界**を見る」を強調する |
| 否定役が褒め始める | 禁止表現の指定が抜けている。「代替案を出すな」「褒めるな」を必ず入れる |
| 1ラウンドで綺麗に終わる | 手加減を疑う。上記の検出手順を飛ばさない |
| 最終戦略が無難で退屈 | 骨抜き。レビュワーの3番目のチェックが効いていない |
| 出典が実在しない | リサーチ役の幻覚。レビュワーに実アクセスで確認させる |

## 前後のスキル

- 前提が曖昧なまま持ち込まれた → 先に `grill-me` で人間に詰めてから入る
- 途中で「そもそも方向が違うのでは」と感じた → `take-a-step-back`
- 出来た戦略を社外に出す → `distribution-check` を通す
- Plaud録音が入力 → `plaud-shared` → `plaud-find` → `plaud-read`

**`grill-me` との違い**: grill-me は**人間に**聞く。strategy-council は**AIが戦略を殴る**。人間の前提を固めるのが前者、固まった案を壊しにいくのが後者。
